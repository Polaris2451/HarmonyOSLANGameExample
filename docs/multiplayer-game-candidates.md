
# 局域网多人联机 — 课程示例游戏候选清单

> 场景约束：**一台服务器（教师机 / 某个同学的本机）+ 若干学生端（模拟器或真机）**，
> 同一个局域网，**不需要端口映射、不需要公网 IP**。
> 所有候选游戏都复用同一套「房间 + 协议 + 权威服务器」骨架，新增一个游戏 ≈ 新增一个 `GameRoom` 子类 + 一组消息类型。

目标技术栈：HarmonyOS 6.0.0 / API 26 客户端（ArkTS + ArkUI）+ 单文件 Node.js 服务器。

---

## 一、选型维度

| 维度 | 说明 |
|---|---|
| **回合制 / 实时** | 回合制几乎不需要同步技巧，适合讲「状态机」；实时制需要 tick、插值、延迟处理，适合讲「游戏循环」 |
| **服务器状态量** | 决定快照大小与重连成本。棋盘类 < 1 KB，动作类 < 4 KB |
| **隐藏信息** | 有私有状态（手牌、我的词）的游戏能讲「服务器只下发该发的东西」，这是最容易被学生做错、也最有教学价值的一点 |
| **实现工作量** | 以「能上课演示」为标准，而不是「能上线」 |
| **网络教学点** | 每个游戏应该各自暴露一个不同的网络问题，避免四节课讲同一件事 |

## 二、推荐阶梯（由易到难，四节课的天然顺序）

### 第 1 课 · 五子棋 Gomoku（回合制，2 人）★☆☆☆☆

- **同步模型**：回合制，服务器权威。状态只有 `{ board: number[225], turn: number, winner }`。
- **消息**：`join` / `move{x,y}` / `state` / `event{type:'win'|'draw'|'illegal'}`。
- **教学点**：回合所有权校验（「不是你的回合」）、非法落子拒绝、胜负判定的服务端实现、断线重连的完整快照。
- **为什么放第一**：状态是可打印的二维数组，学生能肉眼 debug；一个下午能做完。

### 第 2 课 · 贪吃蛇大作战 Snake Royale（实时，2-6 人）★☆☆☆☆→★★☆☆☆

- **同步模型**：服务器 10 Hz tick，网格移动（回合制化的实时），客户端插值。
- **状态**：每条蛇 `{ id, body: Point[], dir, alive, score }`，食物列表。
- **教学点**：固定 tick、输入队列与合并（避免按一下转两格）、碰撞判定必须服务端做、死亡与观战。
- **为什么好**：规则比俄罗斯方块简单一个数量级，但把「实时」的全部要素都占了，是俄罗斯方块之前的最佳热身。

### 第 3 课 · 你画我猜 Draw & Guess（回合制 + 实时绘制，3-8 人）★★☆☆☆

- **同步模型**：回合制状态机 `lobby → choosing → drawing → reveal → scoreboard`，其中 `drawing` 阶段是流式笔迹广播。
- **状态**：笔迹列表（归一化坐标！）、当前画笔、猜对名单、分数。
- **教学点**：**私有信息下发**（答案只发给画手，其他人只看到字数占位）、笔迹批量传输与限流、服务端计时器、猜词归一化。
- **最容易做错的一点**：把答案广播给所有人再用 UI 藏起来 —— 抓包就穿帮。必须服务器分层下发。

### 第 4 课 · 俄罗斯方块对战 Tetris Battle（实时，2-4 人）★★★☆☆

- **同步模型**：服务器权威，每人独立棋盘，消行向对手发垃圾行。
- **教学点**：7-bag 随机与确定性（服务器发牌，客户端不复现随机）、输入节流（DAS/ARR 合并）、垃圾行抵消、淘汰与结算、快照重连。
- **注意**：这是四个里唯一需要「每个玩家一份独立状态」的，正好讲状态隔离。

> 四节课的网络知识点互不重复：回合校验 → 固定 tick + 输入合并 → 私有信息 + 流式广播 → 每玩家状态 + 确定性随机。

## 三、其他候选（可按课时与班级水平替换）

### A. 高性价比 · 低难度

| 游戏 | 人数 | 同步 | 服务器状态 | 教学点 | 工作量 |
|---|---|---|---|---|---|
| **抢答问答 Quiz Buzz** | 3-20 | 实时 | 当前题号、抢答者、计分 | 广播与「谁先到」的公平判定（用服务器到达顺序，不用客户端时间） | 极低 |
| **猜数字 / 数字炸弹** | 2-10 | 回合制 | 区间、当前玩家 | 最小可用协议；适合第一节课讲握手 | 极低 |
| **21 点 Blackjack** | 2-6 | 回合制 | 手牌（私有）、庄家牌（半隐藏） | 私有状态 + 隐藏信息；`reveal` 时机 | 低 |
| **词语接龙** | 2-8 | 回合制 | 上一个词、已用词集合 | 服务器校验字典、超时判负 | 低 |
| **井字棋 Tic-Tac-Toe** | 2 | 回合制 | 9 格 | 五子棋的超简版，适合做协议原型 | 极低 |

### B. 中等难度 · 教学价值高

| 游戏 | 人数 | 同步 | 教学点 | 工作量 |
|---|---|---|---|---|
| **谁是卧底 / 词语推理** | 4-8 | 回合制 | 角色私有下发、投票流程、发言阶段状态机 | 中 |
| **乒乓球 Pong 对战** | 2 | 实时 60 Hz | 连续物理 + 客户端插值 + 延迟补偿（比网格游戏更依赖插值） | 中 |
| **简化坦克大战** | 2-4 | 实时 20 Hz | 子弹与碰撞、命中判定、延迟下的「我明明躲开了」 | 中 |
| **大富翁简化版** | 2-4 | 回合制 | 复杂状态机 + 骰子随机数服务端权威 + 交易协商 | 中高 |
| **合作扫雷 / 合作拼图** | 2-4 | 实时 | 共享单一状态 + 操作合并冲突 | 中 |

### C. 不建议作为课程主线

- **狼人杀**：流程和发言阶段极复杂，60% 的工作量在状态机而非网络，容易烂尾。
- **FPS / 动作射击**：需要预测-回滚、命中回溯，超出课程范围。
- **需要公网/账号的游戏**：违反「局域网、零配置」前提。

## 四、P2P / 房主模式：什么时候用

| 方案 | 适用 | 代价 |
|---|---|---|
| **权威服务器**（推荐） | ≥ 2 人、需要可信计分、要支持重连/观战 | 需要一台机器跑 Node（教师笔记本即可） |
| **房主即服务器** | 只有两台设备、没有电脑 | 用 `socket.constructTCPSocketServerInstance()` / `webSocket.createWebSocketServer()` 在 App 内起服务；房主有优势、切后台即掉线 |
| **纯 P2P** | 课堂演示「去中心化」概念 | NAT 穿透、状态分歧、无法防作弊，不建议作为评分作业 |

结论：**主线用权威服务器**；把「房主模式」做成一个 `Transport` 的另一实现，作为进阶选修 —— 架构上二者可替换，这也是讲「依赖抽象而非实现」的好素材。

## 五、共同的技术骨架（所有候选游戏共用）

~~~text
server/
  index.js          房间注册表 + WebSocket 接入 + 心跳
  room.js           房间基类：tick、广播、快照、加入/离开
  games/
    gomoku.js
    snake.js
    drawguess.js
    tetris.js
client (entry/src/main/ets)/
  core/             协议类型、纯规则（可脱离设备单测）
  net/              Transport 接口 + WebSocket 实现 + 重连
  viewmodel/        @ObservedV2 状态store
  pages/            ArkUI 页面（只绑定状态 + 调 viewmodel）
~~~

一个游戏 = 实现 `GameRoom` 的 `onJoin / onMessage / step / snapshot` + 客户端一个 store + 一个页面。

## 六、课堂部署（零端口映射）

1. 教师在笔记本运行 `node server/index.js`，服务器启动时**打印本机局域网 IP**（`ipconfig getifaddr en0`）。
2. 学生真机连 `ws://<教师IP>:8080/game?room=ABC`，确保同一 Wi-Fi、关闭 AP 隔离。
3. **模拟器**连不到局域网 IP（NAT），用 `10.0.2.2` 指向宿主机，或 `hdc fport tcp:8080 tcp:8080` 后连 `127.0.0.1:8080`。
4. macOS 首次运行 Node 会弹防火墙授权，需点「允许」。
5. 不要硬编码某个学生的 IP；把服务器地址放进 `resources/rawfile/config.json`，改配置不重新编译。

## 七、下一步建议

1. 先落地 `server/index.js` + `core/协议` + `Transport` 抽象（本清单的第五节）。
2. 用**五子棋**打通端到端（握手、房间、重连、单测）。
3. 再按第 2 → 3 → 4 课的顺序加 `snake` / `drawguess` / `tetris`，每个游戏只新增 `games/xxx.js` 与对应页面。
