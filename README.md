# HarmonyOS局域网联机实战案例

一个面向**课程教学**的 HarmonyOS 联机游戏项目：局域网下就能开局，**不需要公网服务器、不需要账号、不需要后端**。

房间由其中一台设备临时充当「房主」——它同时是服务端和玩家；其余设备作为客户端加入。

> 内置三个游戏：**五子棋** · **你画我猜** · **俄罗斯方块对战**


---

## 三个游戏

| 游戏 | 人数 | 玩法 |
|---|---|---|
| **五子棋** | 固定 2 人 | 15×15，先连成五子者胜；支持认输、再来一局 |
| **你画我猜** | 2–8 人 | 每轮一人作画，其余人抢答；共 3 轮，选词 15 秒 / 作画 75 秒 / 揭晓 5 秒 |
| **俄罗斯方块对战** | 固定 2 人 | 各自 10×20 棋盘，消行给对方送垃圾行，先顶死的一方输 |

## 系统要求
 HarmonyOS 6.1 及以上（API 23+） 
## 快速开始

### 1. 打开工程

用 **DevEco Studio** 打开项目根目录，等待右下角的 Sync 完成（它会自动补上 `oh_modules` 和 `local.properties`）。

### 2. 配置签名

第一次打开后要自己配一次：

> **File → Project Structure → Signing Configs → 勾选 「Automatically generate signature」→ Apply**

需要登录华为开发者账号。它会把签名配置写回 `build-profile.json5`。

### 3. 构建与运行

```bash
# 命令行构建（需要 DEVECO_SDK_HOME 和 JAVA_HOME）
export DEVECO_SDK_HOME=/Applications/DevEco-Studio.app/Contents/sdk
export JAVA_HOME=/Applications/DevEco-Studio.app/Contents/jbr/Contents/Home

/Applications/DevEco-Studio.app/Contents/tools/hvigor/bin/hvigorw \
  assembleHap --mode module -p product=default
```

产物在 `entry/build/default/outputs/default/` 下。
配置好签名后，直接在 DevEco 里点运行按钮即可。

### 4. 联机

1. 房主设备：**创建房间** → 选游戏 → 选端口（默认 8080）→ 填昵称 → 创建
2. 加入方：**加入房间** → 填房主的**地址和端口** → 填昵称 → 加入
3. 人数够了以后，**由房主点「开始游戏」**（人数不够时按钮是灰的）

# 网络配置教程

## 一、场景

| 房主 | 加入方 | 要配置吗 | 加入方填什么 |
|---|---|---|---|
| 真机 | 真机 | **不需要** | 房主的局域网 IP，例如 `192.168.1.50:8080` |
| 真机 | 模拟器 | **不需要** | 房主的局域网 IP，例如 `192.168.1.50:8080` |
| **模拟器** | 模拟器 | **需要** | 同机：`10.0.2.2:8080`　跨机：`<宿主机IP>:8080` |
| **模拟器** | 真机 | **需要** | `<宿主机IP>:8080` |

为什么会这样：

- **真机当房主**：它本来就在局域网上，其他设备直接连它的 IP 就行。
- **模拟器当房主**：应用在模拟器**内部网络**里监听 8080，这个端口从外面看不见，必须做端口映射把它「拉」出来。
- **模拟器当加入方**：它是主动往外连的（出站流量），宿主机不需要任何配置。

## 二、配置流程

### 第 1 步 · 把 hdc 加进 PATH

`hdc` 是鸿蒙的命令行调试工具（相当于 Android 的 adb），DevEco Studio 自带，但它所在的目录默认不在系统环境变量里，所以直接敲 `hdc` 会提示找不到命令。

#### Windows

1. 进入 DevEco Studio 安装目录下的 `sdk\default\openharmony\toolchains\`，确认里面有 `hdc.exe`
2. 复制这个目录的完整路径，例如 `D:\DevEco Studio\sdk\default\openharmony\toolchains`
3. 「此电脑」右键 → 属性 → 高级系统设置 → 环境变量 → 在「系统变量」里选中 `Path` → 编辑 → 新建 → 粘贴路径 → 一路确定
4. 关掉所有已打开的 cmd / PowerShell，**重新开一个窗口**
5. 验证：`hdc -v` 能输出版本号即成功

#### macOS

hdc 在 DevEco Studio 应用包内部：

```
/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc
```

把它的**目录**追加进 PATH：

```bash
open -e ~/.zshrc
```

在文件末尾加一行（路径按你机器上的实际版本调整）：

```bash
export PATH=$PATH:/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains
```

保存后生效并验证：

```bash
source ~/.zshrc
hdc -v
```

### 第 2 步 · 设置端口映射（hdc fport）

先确认设备连上了，并记下**房主那台模拟器的序号**：

```bash
hdc list targets
```

```
127.0.0.1:5555
127.0.0.1:5557
```

应用在模拟器内部监听 8080，用 `fport` 把它拉到电脑上：

```bash
hdc -t 127.0.0.1:5555 fport tcp:<宿主机端口> tcp:8080
```

**宿主机端口怎么选**，取决于加入方在哪：

| 加入方在哪 | 命令 | 加入方填 | 还要做第 3 步吗 |
|---|---|---|---|
| 同一台电脑上的另一个模拟器 | `hdc -t 127.0.0.1:5555 fport tcp:8080 tcp:8080` | `10.0.2.2:8080` | 不需要 |
| 真机 / 别的电脑 | `hdc -t 127.0.0.1:5555 fport tcp:18080 tcp:8080` | `<宿主机IP>:8080` | 需要 |

查看与删除：

```bash
hdc fport ls                    # 查看当前映射
hdc fport rm tcp:18080 tcp:8080 # 删除指定映射
```

#### 两台模拟器都想当房主？

给它们各绑一个宿主机端口，两条映射可以**同时存在、互不冲突**——关键是用不同的宿主机端口：

```bash
hdc -t 127.0.0.1:5555 fport tcp:8080 tcp:8080
hdc -t 127.0.0.1:5557 fport tcp:8081 tcp:8080
```

于是：

- **5555 当房主** → 加入方填 `<宿主机IP>:8080`
- **5557 当房主** → 加入方填 `<宿主机IP>:8081`

**连接前先确认当前是谁当房主，填对应的端口。** 如果加入方是同一台电脑上的另一个模拟器，则对应填 `10.0.2.2:8080` 或 `10.0.2.2:8081`。

两台模拟器分别在两台电脑上时，各自做一遍本教程的四步，互不影响。

### 第 3 步 · 设置宿主机端口转发

**仅当加入方不在这台电脑上时需要。** 上一步的映射只让宿主机自己看得见，这一步把它暴露到局域网网卡。以下对应第 2 步表格里的第二种情况（映射在 18080）。

#### macOS ：socat

socat 通过 Homebrew 安装。Homebrew 下载地址：<https://brew.sh/zh-cn/>

```bash
brew install socat

socat TCP-LISTEN:8080,fork,reuseaddr TCP:127.0.0.1:18080
```

`TCP-LISTEN:8080` 默认绑所有网卡，`fork` 表示支持多人同时连接。这个窗口要保持开着。

#### Windows：netsh 端口转发

以**管理员身份**打开 PowerShell 或 cmd：

```cmd
netsh interface portproxy add v4tov4 ^
  listenaddress=0.0.0.0 listenport=8080 ^
  connectaddress=127.0.0.1 connectport=18080
```

查看与删除：

```cmd
netsh interface portproxy show v4tov4
netsh interface portproxy delete v4tov4 listenaddress=0.0.0.0 listenport=8080
```

### 第 4 步 · 防火墙设置

| 系统 | 做什么 |
|---|---|
| **Windows** | 管理员窗口执行：`netsh advfirewall firewall add rule name="HarmonyOS Game 8080" dir=in action=allow protocol=TCP localport=8080 profile=domain,private`　只放行**域**和**专用**网络，没必要对「公用网络」开放。或者第一次启动转发程序时，在弹出的对话框里**只勾选「专用网络」**再点允许。 |
| **macOS** | 系统防火墙默认关闭，通常什么都不用做。若曾经手动开过，第一次监听端口时会弹窗询问，点**允许**即可。 |

### 配置完成后的自检

| # | 命令 | 看到什么算对 |
|---|---|---|
| 1 | `hdc -v` | 输出版本号 |
| 2 | `hdc list targets` | 列出模拟器 / 真机 |
| 3 | `hdc fport ls` | 能看到刚建立的映射 |
| 4 | macOS：`lsof -nP -iTCP:8080 -sTCP:LISTEN`　Windows：`netstat -ano + findstr :8080` | 看到 `*:8080` 或 `0.0.0.0:8080` |
| 5 | 另一台设备浏览器打开 `http://<宿主机IP>:8080` | 不是「无法连接」就说明通了 |
| 6 | App 加入房间，填上表里的地址 | 房主看到人数变成 2/2，「开始游戏」可点 |

### 关于 10.0.2.2 地址

1. `10.0.2.2` 指向的是**宿主机的 `127.0.0.1`**，不是某个真实网卡地址
2. 它同时是模拟器的**默认网关**——模拟器访问外网（包括局域网里其他设备）都从这里出去

所以**只有跑在同一台电脑上的模拟器**能用它；别的设备填 `10.0.2.2` 会指向它自己，必然连不上。

## 四、错误自查

### 关于 hdc

| 现象 | 原因与修法 |
|---|---|
| `'hdc' 不是内部或外部命令` / `hdc: command not found` | toolchains 目录没进 PATH。Windows 改完环境变量后要**重新开终端**；macOS 记得 `source ~/.zshrc` |
| macOS 提示 `Permission denied` | `chmod +x /Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc` |
| `hdc list targets` 是空的 | 模拟器没启动，或真机没开「开发者模式 + USB 调试」、没在弹窗里点允许。真机还要用数据线而不是纯充电线 |

### 关于端口映射

| 现象 | 原因与修法 |
|---|---|
| 模拟器重启后突然连不上 | `fport` 的映射随模拟器重启丢失。`hdc fport ls` 显示 `[Empty]` 就是丢了，重新执行第 2 步 |
| 两个模拟器不能同时映射 | 宿主机**同一个端口**只能指向一台设备。给它们各绑一个端口（如 8080 和 8081），见第 2 步 |
| 不写 `-t` 时不知道作用在哪台设备 | 接多台设备时**务必带 `-t <设备序号>`**，否则可能作用到你不想要的那台上 |

### 关于端口转发与防火墙

| 现象 | 原因与修法 |
|---|---|
| 转发程序报「地址已被占用」 | 宿主机的 8080 已经被 `fport` 占用了。按第 2 步表格的第二种情况，把映射改到 18080 |
| **`fport` 只绑回环地址** | 这是最关键的一点：`hdc fport` 监听的是 `127.0.0.1`，**只有宿主机自己**能访问，局域网设备连不上。所以加入方不在本机时，必须有第 3 步的转发 |
| Windows 转发命令执行成功但仍连不上 | ① 没做防火墙放行，连接被静默丢弃；② **IP Helper** 服务（`iphlpsvc`）没运行，`portproxy` 不生效。去「服务」里确认它处于「正在运行」 |
| 手机一直转圈，最后报「连不上」 | 按《配置完成后的自检》从第 3 项往下逐条查 |

### 关于地址填写

| 现象 | 原因与修法 |
|---|---|
| 其他设备填 `10.0.2.2` 连不上 | 它只对**同一台电脑上的模拟器**有效（指向宿主机的 127.0.0.1）。其他设备要填宿主机的局域网 IP |
| 填了模拟器的内部地址 `10.0.2.15` | 那是模拟器自己的地址，只存在于模拟器内部网络，外面访问不到 |
| 宿主机 IP 怎么查 | macOS：`ipconfig getifaddr en0`　Windows：`ipconfig`（看 IPv4 地址） |

### 关于应用本身

| 现象 | 原因与修法 |
|---|---|
| 房主创建房间时提示端口被占用 | 上一次的房间没退干净，或 8080 被别的程序占了。彻底退出应用重进，或在创建页换一个端口 |
| 房间页显示「未连接到局域网」 | 设备没连 Wi-Fi |
| 能连上但一加入就断开 | 两端 App 版本不一致，用同一个安装包 |
| 真机装不上，提示 `device is unauthorized` | 该真机的 UDID 不在签名 Profile 的设备清单里。用 DevEco 的「Automatically generate signature」重新签名 |
| 电脑和手机不在同一个 Wi-Fi | 路由器的 AP 隔离或访客网络会阻止设备互访。先确认连的是同一个 Wi-Fi、同一个网段 |

### macOS

